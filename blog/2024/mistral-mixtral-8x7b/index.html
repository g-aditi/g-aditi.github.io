Open Source vs. Open Weight Models

Making a software open source entails releasing its source code for use, debugging, and modification. This includes use in proprietary software. Open source software is usually human readable, and is therefore, easy to comprehend and utilize. However, with regards to neural networks, the primary logic of the network lies in its weights. These weights are vector representations of everything the network has learnt. These, nevertheless, are not in human-readable format, due to which they are non-trivial for running, usage in other software, and debugging. Therefore, they do not fall perfectly into the open source category.

The question of how to limit the use of neural network weights while adhering to the Four Freedoms of free software is a subject of intense discussion, of which this article by GNU provides a detailed overview.

The Model

The Mixtral-8x7B model uses something called the Sparse Mixture-of-Experts (SMoE) architecture. But to understand SMoE, let us first acquaint ourselves with the idea of a Mixture-of-Experts (MoE) model as proposed in the Adaptive Mixtures of Local Experts paper in the year 1991.

Mixture-of-Experts (MoE): It’s Story Time!

Imagine a group of n friends planning a roadtrip. Each Friend excels in one area, such as driving, navigating, selecting a soundtrack, arranging an itinerary, and so on. One person, the Coordinator, decides which Friend’s skills are relevant for each situation encountered during the trip. In other words, the Coordinator decides which Friend’s opinion is most important during each step of the trip and assigns them the requisite role.

With each roadtrip, the Coordinator learns the strengths and weaknesses of each of the friends and modifies role delegation accordingly. Moreover, each Friend keeps improving on their own skill of doing their specific task.

In an MoE type of model, each Friend is a neural network called an “expert”, and the Coordinator is the “gatekeeper network”. Each expert network is very good at performing a specific use case, and the gatekeeper allocates a use case to one or some of the expert networks. Should the output be incorrect, the weight changes occur on a per-expert (or per-few-expert) case, where the respective expert(s) as well as the gatekeeper network learn the changes. That means that both of these are trained together for ensuring effective application over a variety of use cases.

Architecturally, with MoEs, each feed-forward network layer in the transformer model is swapped out with a MoE layer made up of a certain number of experts and a gate network. The input given to each expert is also given to the gatekeeper network, and while each expert gives one output, the gatekeeper network gives as many outputs as there are experts. The final output is given by the selector, which determines which experts’ outputs to consider. It can select the outputs of one or more experts.

What Does An Expert Learn?

The answer to this question lies in the ST-MoE paper. It was noticed that encoder experts had a focus on a subset of tokens or fundamental concepts. We could, for example, end with a punctuation expert, a proper noun expert, and so on. The decoder experts, however, are less specialized. The authors studied in a bilingual environment as well. While it would be ideal to think of every expert as having a particular language of expertise, the reality is that no expert has a particular language of expertise because of token routing and load balancing.

Sparse Mixture-of-Experts (SMoE)

Mixtral-8x7B is an SMoE model, but what’s that? Equipped with some background knowledge, let’s decode what this new term means.

Sparsity makes advantage of the conditional computation concept. Sparsity enables us to merely run a portion of the entire system, whereas in dense models, all parameters are employed for all inputs. In simpler terms, because only a portion of the network is active for particular inputs, sparsity in MoEs allows for scalability without increasing the amount of computation overall. Making lightweight models is another one of MISTRAL’s tenets, and this new architecture allows them to do exactly that.

The feedforward block selects from a set of eight different groups of parameters in this decoder-only model (hence the 8x). A router network selects two of these groups, or the “experts”, at each layer for each token in order to process it and contribute their output. This part is the same as the MoE model, with the only exception being in the number of experts selected at each layer.

Do read the Outrageously Large Neural Networks paper for an in-depth exploration of this concept.

What Are The Fun Nitty-Gritties?

Mixtral-8x7B is feature rich and easily accessible to the public. Here are some of its best characteristics:

  1. Open under the Apache 2.0 license
    It enables individuals to use, change, and distribute the software for any reason, with or without modifications. Users are also able to sublicense, but they must incorporate the original copyright and provide a license copy. It avoids concerns with patents and liability.
  2. Trained on data obtained from the open web
  3. 32,000 tokens for context
    The model is perfect for tasks needing a deep awareness of context because of its vast context-handling capability, which enables it to interpret and process bigger amounts of data. This is a crucial advancement, especially in cases where sophisticated understanding is required.
  4. Ability to be fine-tuned into an instruction-following model optimized through Supervised Fine-Tuning (SFT) and Direct Preference Optimization (DPO)
    SFT involves retraining a pre-trained model — typically from a large dataset — on a smaller dataset tailored to a specific goal. Gradient descent and backpropagation are used to modify the model’s weights in order to optimize for task-specific goals. For the purpose of improving performance, this procedure makes use of previous knowledge that was contained in the original model and tailors it to the specifics of the target task. More on this in this article.
    Models are directly optimized depending on user preferences using the DPO machine learning technique. Through pairwise comparisons, it learns how to enhance model parameters and formulates optimization targets as preference comparisons. The Your Language Model is Secretly a Reward Model paper talks about this in greater detail.
  5. Master of the English, French, Italian, German, and Spanish languages
  6. Strong performance when it comes to code generation

How Good Is Mixtral-8x7B Really?

Mixtral was contrasted with the base model of GPT-3.5 and the Llama 2 series. Mixtral performs on most benchmarks either on par with, or better than Llama 2 70B or GPT3.5.

Conforming to MISTRAL’s tenet of delivering high-performance and high-quality models, let’s take a look at the quality vs. inference budget tradeoff graphs on multiple factors for the Mixtral model family and LLaMA 2.

When it comes to biases and hallucinations, the base model of Mixtral performed really well w.r.t. BBQ and BOLD.

Mixtral has less bias on the BBQ benchmark than Llama 2. In general, Mixtral exhibits higher levels of positive sentiment on BOLD than Llama 2, with comparable variances observed within each dimension.

In short, Mixtral is a great model both in terms of performance and quality.
